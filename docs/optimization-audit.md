# FullScape 优化审查

日期：2026-10-16（Australia/Brisbane）。分支：`codex/codebase-optimization`，基于 `727220c`（保留最近的动画改进）。创建前已 fetch origin，当前工作区干净。

按要求使用三个 GPT-6.1-sol / medium 子代理，分别检查界面布局和动画、兼容遗留和无用代码、歌词服务和性能安全。主代理重新阅读关键调用链、检查全部修改并运行验证；没有直接照搬未经证实的建议。

## 已确认并修复

| 问题 | 触发及影响 | 修复与验证 |
| --- | --- | --- |
| 重建界面遗漏 React 卸载 | 修改设置或 F11 后直接替换 innerHTML；旧进度条仍保留全局事件、interval、rAF，重复操作累积后台工作 | `app.tsx` 在替换前卸载旧进度条；应用生命周期测试断言清理顺序与最终卸载 |
| 重建界面重复注册队列监听器 | render 未移除宿主 queue_update 上的 Queue.scheduleUpdate，重新 activate 再次添加；EventEmitter 会保留重复订阅 | render 移除旧订阅；测试用保留重复回调的 emitter 验证重建后恰好一次、退出后为零 |
| 关闭歌词跳过旧实例清理 | 配置先变为 false，render 按新配置跳过 teardown；旧歌词节点、动画和桥接状态继续存活 | render 与退出无条件 teardown；生命周期测试覆盖开启→关闭歌词 |
| 语言切换保留启动语言 | app 闭包 LOCALE 从未刷新，侧栏标签、日期与部分通知仍用旧语言 | render 重新读取 locale；测试验证新 data-locale 与侧栏标签 |
| 队列卡片复用保留旧 UID | 同曲目重新加入队列，URI/封面相同、Spotify UID 改变，卡片仍点击旧 entry，播放检查拒绝 | 复用节点后刷新身份与点击绑定，保留卡片及其动画；测试验证相同节点使用新 entry |
| 歌词桥接轮询可重复启动 | bridge GET 未完成时再次 load，timer 已为空，被误判为未启动；旧任务完成后又建立另一条轮询链 | 独立运行状态与 generation；停止后旧结果不发布、不重建 timer、不清除新请求的锁；延迟 Promise 测试覆盖 |
| 缓存丢失手动隐藏语义 | LyricShiori 隐藏歌词后再次播放该曲，本地快路径只读取 lines，歌词重新显示，离线桥接时无法纠正 | 本地命中保留并检查 hidden，不显示、不安排重试；测试覆盖 |
| 关闭桥接仍发送歌词 | 本地 setCachedLyrics 默认同步，底层 POST 入口没有检查开关；关闭后仍尝试发送歌词与元数据 | 写入共享缓存前检查开关；测试验证仍保留本地缓存且零网络请求 |
| 歌词请求去重存在 await 空窗 | 请求 Map 检查与登记之间等待 bridge lease，同曲并发调用可各发一次请求 | 对 Spotify 与增强歌词请求在等待 lease 前登记 Promise，并测试并发与失败重试 |

## 已删除的包袱

- 未使用的 Mousetrap 录制插件，整文件 199 行，含 IE6–9 数组兼容实现；删除其初始化与专用 ESLint 豁免。普通快捷键仍使用宿主 bind/unbind。移除也避免无用途地覆写 Spotify 共用 Mousetrap 原型。
- 旧原生队列侧栏控制方法、状态、专用选择器与对应旧样式。当前队列由独立 Queue 组件实现，没有调用旧路径。
- 无调用的艺术家背景图查询链，包括硬编码旧 Pathfinder 查询 hash；以及无调用的观察器、取色、时钟工具方法。
- 未使用的旧歌词图标、more 图标、ellipsis 源素材及其生成条目。
- 源码无导入的 react-icons 依赖，更新锁文件；安装目录约 83 MB。它原本没有打进 bundle，不能把这 83 MB 当作运行时包体收益。
- CI 和发布流程加入 `npm test`，让现有动画回归测试参与校验。

## 审查后保留

- Kawarp 流体背景、节拍参数、WebGL 失败时的旋转 Canvas 回退：仍有真实调用，不属于无用兼容。
- 封面入场、队列交接、卡片复用与布局动画、Up Next 飞入、逐词歌词和文字溢出滚动的实现与时序。
- Spotify 队列 API 兼容与 UID 检查：关系到不同宿主及设备状态下的可靠播放，不能只凭备用分支判定过时。
- 响应式/竖屏样式：未证实另有必须修改的布局错误，未进行大范围样式重写。
- lodash.defaultsdeep 的语言字段回退、marked 的更新说明解析、React 与 classnames：均有实际消费者。
- 更新器的 SHA-256 校验、运行版本握手、失败回退及选版模型：仍是有效的安全与恢复机制。

## 未纳入本轮的低收益项

- 队列可见或用户手动隐藏歌词时，歌词仍继续同步；暂停它需要验证恢复后的逐词时序。本轮优先保持动画，不引入这类行为调整。
- Up Next 空的 secondaryText 结构和少量写入兼容字段仍可继续精简，但收益小于本次已确认问题。
- 测试使用的 esbuild 目前来自 spicetify-creator 的传递依赖；未在本轮调整构建工具版本。

## 验证边界

验证通过：`npm run check`（TypeScript + ESLint）、`npm test`（77/77，比基线新增 7 项）、`npm run build-local` 和 `git diff --check`。压缩 bundle 从 1,633,820 字节变为 1,624,509 字节，减少 9,311 字节（约 0.57%）；主要收益是删除死代码和消除重复后台工作，而非大幅缩小已有有效依赖。新增测试使用可控 DOM/宿主桩与延迟 Promise，覆盖实际编排和并发行为；现有封面、队列、Up Next、motion、歌词和更新校验测试继续通过。重新生成 `dist/fullscape.js`。

没有在真实 Spotify 窗口安装此分支进行截图或逐帧视觉对比，因此“动画保持”有源码差异与自动回归依据，但还不是实际宿主视觉验收。没有确认额外的高危安全漏洞；该结果不等同于证明不存在漏洞，也没有据此无差别删除兼容分支或升级依赖。
